# Circuit Harness 测试记录模板

复制到本人私有的 `runs/chips/validation/<run-id>/record.md` 或部署归档位置后填写。
这是记录模板，不会执行命令或授予外部操作权限。对外只分享审查过的脱敏版本。

## 范围与约束（运行前）

- run ID / 时间 / 操作者：
- 关联 issue / 案例 ID / 预期行为：
- 测试层次：本地回归 / 只读巡检 / 实验室 / 模型 E2E / 对照实验
- 真实组件与构造替身分别是什么：
- 现有授权覆盖的主机、数据、模型、资源/费用预算：
- 停止条件 / 超时 / 清理和恢复范围：
- 通过条件、数值容差、比较指标与重复次数依据：
- Agent 所在机器、Agent/CLI 版本、模型 provider/ID、登录方式（不写凭据）：
- 本次思考模式／推理档位：Pi `thinking` 或原生 Codex `reasoning_effort`；模型支持的取值与配置来源：
- `local` 或 SSH Tool 传输、服务器任务会话、可见 Tool 集合及提示版本：
- 仿真器/执行后端、许可证或镜像条件、独立终评入口：
- 模型请求、公开仿真、资源和费用预算：
- Agent 轨迹、服务器动作与仿真证据、最终私有归档分别位于何处：

## 复现输入

- Git commit、分支、未提交改动说明或补丁摘要：
- 测试脚本/输入/配置/工艺的版本或摘要（不写凭据）：
- 软件、Python、Agent、provider/model 版本与采样设置：
- 私有环境配置位置、工作目录及存储类型：
- 每条实际执行命令和退出码：
- 性能比较中的运行顺序、线程数、并发负载、首次/重复运行标记：

## 执行证据

| 检查 | 阶段（Red/Green/回归/实验） | 状态 | 实测值/失败原因 | 原始证据路径及摘要 |
| --- | --- | --- | --- | --- |
| 填写检查名称 | 填写实际阶段 | passed / failed / blocked / not_run | 无测量则写未测量 | 对应日志/JSON/JUnit/产物 |

测试汇总：执行数、通过数、失败数、skip/xfail 数及原因。
没有执行、全部 skip、替身通过不能填写真实实验室或模型验收通过。
补测试时不要补写未发生的 Red；将外部故障和实现错误区分记录。

## 结论与归档

- 本次证据支持什么、不能支持什么：
- 与比较方案的差异、波动和仍存在的混杂因素：
- 未通过项、恢复状态、剩余依赖：
- 产物 manifest / 校验和 / 归档位置 / 保留策略：
- 是否清理了本次隔离资源（未清理则写明）：

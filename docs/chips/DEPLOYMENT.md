# Circuit Harness 部署规范：目录、访问边界与模型网络

本文补充 [平台路线图](ROADMAP.md)。
适用于个人部署和小组协作；是部署约定及验收要求，不代表这些检查已经在 Harness 中实现。
实际服务器路径、账号、权限审计和网络证据保存在操作者本地，不写入仓库。
源码、配置模板与实验数据的对外发布范围见[仓库发布边界](REPOSITORY_SCOPE.md#publication-boundary)。

## 1. 文件放在哪里

以实际部署配置映射以下逻辑位置。变量名用于说明约定，目前不是已经实现的配置字段。

| 逻辑位置 | 内容 | 存储选择 | Git 管理 |
| --- | --- | --- | --- |
| `CHIPS_CODE_ROOT` | `main` checkout、任务定义、Tools、测试、小型可共享夹具 | 用户私有持久目录；每位成员有自己的 checkout | 审查后的源码进入公开仓库 |
| `CHIPS_ENV_ROOT` | Python 环境、固定版本 Agent CLI、依赖缓存 | 可信的本人目录；与代码版本关联 | 保存依赖声明，不提交整个环境 |
| `CHIPS_CONFIG_ROOT` | 本机部署配置、路径映射、模型 endpoint 引用 | 用户私有持久目录 | 只提交无敏感信息的模板 |
| `CHIPS_RUN_ROOT` | 每次运行的输入副本、GDS、网表、临时结果、阶段日志 | 优先使用获准的本地 SSD scratch | 不提交 |
| `CHIPS_ARCHIVE_ROOT` | 完整结果、manifest、摘要、校验和、复现证据 | 用户私有持久存储；可为 NFS | 不提交大型或受限产物 |
| `CHIPS_SECRET_ROOT` | 凭据或受控凭据存储的接入配置 | 单独的私有位置；与项目和输出目录隔离 | 永不提交 |
| PDK / license / 公共 EDA 安装 | 工艺和共享工具 | 由实验室管理，只按授权路径引用 | 不复制到仓库 |

每次运行使用唯一 `run_id`；阶段重试保留同一逻辑 job 身份。当前归档状态与计时保存最近一次尝试，
需要长期比较多次失败时，操作者应在重试前保存状态快照。
运行目录示意如下，各名称是目标约定，现有 EMX 产物格式仍以执行器为准：

```text
<private-run-root>/<run-id>/
  manifest.json
  inputs/
  work/
  logs/
  artifacts/
  metrics.json
  result.json
```

归档成功应同时满足终态已记录、必需文件齐备、校验通过；只有归档确认后的可再生 scratch
才可按明确保留期清理。失败任务也保留诊断证据。NFS 持久化不等于已经有备份，需单独确认恢复机制。
初期不默认开启自动清理，也不把未知文件当作本项目 scratch 删除。

同一源码包的 NFS/本地 XFS 对照、真实 EVAS/RC 检查和归档试验见
[存储验证记录](STORAGE_VALIDATION.md)。后台 RC/VABench 已提供 `--root` / `--archive-root`、
自动归档、归档单独重试和显式校验后清理，详见 [存储使用说明](STORAGE.md)。
表中的环境变量仍是逻辑约定；自动选盘、源码/环境迁移和保留期调度尚未实现。
Harbor 的实际镜像、容器资源与预检合同见[服务器部署](HARBOR_DEPLOYMENT.md)。
旧运行配置不自动成为 Harbor JobConfig，各部署分别验收。

## 2. 谁可以看见

GitHub 仓库权限与服务器文件权限是两个独立边界；源码公开不会开放服务器和运行存储。

| 对象 | 边界 |
| --- | --- |
| 不同 Linux UID 的普通用户 | 由整个父目录链、owner/group、mode 和 ACL 决定是否可列目录、进入、读取 |
| 共用同一 Linux 账号的人和程序 | 共享 UID，普通 `chmod` 无法区分；同账号下的 Agent 也在此范围内 |
| root、具备相应 sudo 权限的管理员、存储管理员 | 不能用普通目录权限保证对其保密 |
| GitHub 协作者 | 源码可公开读取，写入按仓库授权；GitHub 权限不自动授予服务器权限 |
| 模型服务或网关 | 能接收实际提交的 prompt 和工具输出；私有运行目录不意味着这些内容不外发 |

个人模式要求：

- 先确认使用独立账号。部署进程设置 `umask 077`，私有目录设 `0700`，普通敏感文件设 `0600`；
  程序只按执行需要增加权限。umask 只影响新建文件，不会修正既有文件和默认 ACL。
- 检查 ACL，包括父目录上的默认 ACL；不能只看末级目录的 `chmod` 数字。
- 不递归改变整个 HOME 或公共磁盘的权限。对本人新增的项目目录进行精确设置和检查。
- 若 scratch 父目录是所有人可写且没有 sticky bit，即使子目录为 `0700`，其他用户仍可能重命名
  父目录下的条目。优先请管理员提供受保护的个人目录/父目录；在修复前不将其视为可信代码或凭据位置。
- 外层目录名、任务进程名和部分元数据可能仍可见；不要承诺“其他人无法知道项目存在”。
- 凭据不放在命令行参数、任务输入、Git remote URL、日志和结果包中。日志和 Agent 轨迹默认按私有数据管理。

多人协作时，每人使用独立 Linux 账号和 Git checkout。通过公开仓库协作可分享的代码；确需共享受限数据时，
由项目专用组或限定到具体用户的 ACL 授权，明确只读/读写和默认继承规则。
项目共享目录可采用 setgid 目录及受控组权限，但不能默认把整个实验室组当成项目组。
个人模型凭据不随项目组共享。撤销 GitHub 权限和撤销服务器权限分别操作。

`.gitignore` 只控制未跟踪文件的默认提交行为，不是访问控制，也不会移除已跟踪内容。
推送前检查 staged diff；真实部署配置、PDK、许可证信息、原始轨迹和密钥不能提交到源码仓库。

## 3. Agent、Harness 与网络的部署选择

| 方案 | 适用条件 | 数据流 |
| --- | --- | --- |
| Agent + Harness 都在仿真服务器 | 服务器身份隔离、模型出口和认证都验证可用 | 输入转换、仿真、解析就地完成；模型请求仍访问外部 endpoint |
| Agent 在本机或获准的控制节点，Harness 在仿真服务器 | 服务器模型出口尚未可用，或不适合保存个人模型凭据 | SSH 提交任务/查询状态，返回必要指标与日志；大体积仿真文件留在服务器 |
| 服务器 Agent 使用机构提供的模型网关 | 网关访问与模型使用获准，模型身份、接口和数据处理范围明确 | Agent 访问配置的网关；记录真实模型/provider 和路由身份 |

第二种方案仍能把转换、仿真、解析组成服务器内的闭环。Agent 不与仿真进程同机，不代表每轮都要
下载 GDS、波形和完整日志。当前 EMX 实现仍是 SSH/scp 流程；服务器本地后端、按需产物获取和上述
统一目录映射需要后续实现，不能仅靠本文件视为已支持。
新增 [ngspice RC 后端](NGSPICE.md) 已实现独立的服务器本地生成、执行和解析；
不表示现有 EMX 传输、模型网络或通用后台作业服务已完成改造。

连接诊断依次检查：

1. **DNS**：实际模型、登录 endpoint 是否解析；结果是否合理。CDN 可能因网络位置返回不同地址，
   不能只凭不同 IP 判断污染。
2. **TCP 443**：是否建立连接，区分超时、拒绝和 IPv4/IPv6 路由差异。
3. **TLS**：证书链、SNI 和机构 CA 是否正确；不以关闭证书验证作为修复。
4. **HTTP**：无凭据探测只证明连通性或拒绝状态。401/403 不能证明模型调用成功。
5. **认证与协议**：按实际 provider、账号和 CLI 版本验证最小请求，再验证 streaming 和一次工具调用。

`ping` 使用 ICMP，不能代替 HTTPS 检查。网站首页可达、模型 API 可达和登录可用也需要分别验证。
先由网络管理员确认 DNS、出口防火墙、组织支持的代理/模型网关以及服务可用条件；不要直接修改
共享服务器的 DNS、防火墙或代理，也不要将网上找到的固定 IP 写入 hosts 作为持久部署方案。
短暂网络失败采用有界重试；持续路由故障、认证失败和策略拒绝应分类报告，不能无限重试。

## 4. Codex 的具体边界

Codex 支持 ChatGPT 登录或 API key，两者的认证和计费不同。无 GUI 服务器可以在网络可用后
使用 device code 登录；这只解决登录交互，不解决服务器无法连接服务的问题。
自动化采用哪种身份，应与实际账户和组织授权一致，不将用户已有 ChatGPT 订阅当作 API key 额度。

Codex 可配置 custom provider 的 `base_url`、认证来源和协议。机构已有网关时，应验证实际模型、
Responses/streaming/tool-call 兼容性及所安装 CLI 的支持情况。普通 Chat Completions 转发地址
不自动等于可用的 Codex 后端。HTTP 代理的出口转发与 custom provider 的模型 API 网关也不是同一配置。

机构 TLS 代理如使用私有 CA，应采用其可信 CA 配置并核对 CLI 版本；不使用 `curl -k` 或全局关闭 TLS。
保存到文件的 Codex `auth.json` 应按密钥保护。在账号独立性和目录权限确认前，不复制个人登录缓存到服务器。

依据：[官方认证说明](https://developers.openai.com/codex/auth)、
[自定义模型 provider](https://learn.chatgpt.com/docs/config-file/config-advanced#custom-model-providers)。
官方当前文档可能领先于已安装 CLI；部署时需要逐项验证，不静默升级共享工具。

## 5. 纳入 Harness 的 preflight（待实现）

除解释器、软件、许可证和工艺检查外，还应记录并检查：

- 身份：有效 UID、目录 owner、是否使用共享账号；账号共享情况不能仅靠 UID 自动判断，需操作者声明。
- 存储：规范化路径、父目录/符号链接边界、ACL、默认权限、本地盘/NFS、可用空间及配额。
- 网络：所需 endpoint 的 DNS/TCP/TLS 状态和认证验证级别；配置来源不输出秘密。
- 作业：唯一 run/job 身份、CPU/内存/许可证预算、超时/取消、断线后恢复、归档和保留策略。
- 数据：哪些材料可以提交给模型，日志和工具结果的最小必要输出；受限工艺需要另行确认模型外发授权。

对凭据目录暴露、目标目录非本人控制等确定风险，应停止相应部署步骤并给出可复核原因；
纯本地、无需模型的仿真检查不应因模型 endpoint 不可用而整体被阻塞。
部署验收记录需区分“规则已定义”“权限已配置”“运行已验证”，不能混为一个成功标志。

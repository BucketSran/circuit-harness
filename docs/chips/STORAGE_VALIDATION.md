# 存储验证与管理员反馈

本页保留固定条件下的历史测量与验收边界。
这是 2026-09-22 的受控小规模测量，不是生产存储方案已经全部实现的声明。
原始路径、ACL、运行记录和完整电路产物保存在 operator 私有证据目录。

## 同一源码包对照

- Linux x86_64、Python 3.12.10；HOME 为 NFSv4，本地测试目录为 XFS。
  文件系统类型不能证明物理介质是 SSD，也不能确定临时目录的清理策略。
- 固定 VABench r53 的依赖子集：795 个文件，内容合计 9,367,680 字节；gzip 包 1,867,703 字节。
  归档 SHA-256：`4451ac741c042de759c5878665ff320bd3736b2749a3121277bfde485a03c232`。
- 用同一份内存归档，三轮分别按 NFS→本地、本地→NFS、NFS→本地顺序展开到新目录。
  每轮校验全部文件名与内容，再重复校验一次；六次展开、十二次校验全部一致。
- 同一进程与最小环境，保留系统缓存，无并发测试作业。观测到的一分钟系统负载为 0.52–1.02，
  主机有 64 个逻辑 CPU；没有清缓存、修改 NFS 挂载或共享系统配置。

它们不代表 EVAS 求解器加速倍数，也不证明 NFS 服务端的具体故障原因。
归档已读入内存，测量不包含 SSH 上传；展开没有逐文件 fsync，不是持久化吞吐测试。
只有三个配对样本，不报告 p95 或长期稳定性结论。

Python/EVAS 环境仍共用 NFS 上的原安装，没有移动虚拟环境。

## 复现入口与边界

## 可反馈给管理员

在同机、同输入、交替顺序的三轮试验中，795 文件的展开耗时为 NFS 约 15.7–15.9 秒、
本地 XFS 约 0.163–0.167 秒，文件哈希完全一致。请协助：

1. 提供推荐的个人本地 scratch 目录，确认配额、inode 限额、访问权限、自动清理与重启保留策略。
2. 对照测试时间窗口查看 NFS 元数据操作延迟、RPC 重传、网络和服务端存储负载，判断差异原因。
3. 确认归档空间的配额与备份政策，以及后台任务/调度器的退出登录和资源回收规则。

建议先采用本地源码缓存和作业目录、持久存储归档的布局。
保留 pin/hash 校验；归档确认前保留本地完整作业，归档重试不应重新执行仿真。
本次只验证本人新目录，没有调整共享服务器配置。

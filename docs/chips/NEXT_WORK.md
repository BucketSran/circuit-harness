# Chips 平台后续工作与验收计划

更新：2026-09-25。本文把讨论收敛为可执行工作包；**计划不代表功能已实现**。
研究方向见 [ROADMAP.md](ROADMAP.md)，实际通过的检查见 [VALIDATION.md](VALIDATION.md)，
开发与记录方式见 [DEVELOPMENT_SOP.md](DEVELOPMENT_SOP.md)。集成目标是公开仓库
`BucketSran/circuit-harness` 的 `main`；旧参考材料不承担 Chips 运行验收。

2026-09-25 的[Harness 对齐改进方案](HARNESS_ALIGNMENT_PLAN.md)保留全局候选路线。
后续逐项 review 的首项是[Runtime／Environment 实验方案](experiments/runtime-environment/README.md)：
先验证同一 Chips 任务环境接入 Apollo 原生／外部 Runtime，分开契约、故障和真实闭环验收；
目前为待 review 草案，不代表开始实施或已有新实验结果。

## 目标与边界

平台同时服务两种使用方式：

1. **个人实践**：研究者带来文档、图片或口头描述，经本人确认后生成任务，在受控环境中反复设计和仿真。
   可以有人工判定或尚未确定的目标；这类运行仍保存完整证据，但不能直接计入 benchmark 成绩。
2. **可比较评测**：任务、可见输入、工具、软件环境、预算和独立评分规则先冻结，之后才比较
   Tool、Agent、模型或 Memory 的效果。每次只改变声明的实验因素。

两种方式共用任务身份、执行协议、轨迹与归档。个人任务只有补齐参考基线、正反例、评分规则、
数据划分及复现证据后，才能晋升为正式评测任务。原始轨迹是证据，不自动成为下一位 Agent 的记忆。

```text
文档/图片/专家描述
  → 来源可追溯的需求草案 → 研究者确认 → 版本化任务
  → 环境预检 → Agent/人修改候选 ↔ 公开仿真 Tool
  → 冻结提交 → 独立终评/人工审核 → 私有归档
                                      ↓
                         复盘 → 可验证的经验候选 → 冻结 Memory
```

## 现有基线：哪些已证实

| 链路 | 当前证据 | 不可外推的部分 |
| --- | --- | --- |
| EMX | 厂商示例的 JSON→GDS→SSH→EMX→结果回收、哈希与同 ID 恢复；见 [基线](BASELINE.md) | 真实工艺/端口任务、专家认可的电路指标和第二位成员复现 |
| ngspice | lab-server 上理想 RC 的 AC/瞬态、解析校验、后台作业和真实 SSH 断线；见 [说明](NGSPICE.md) | 复杂电路、PDK 和 Agent 自主设计 |
| Spectre | lab-server 上固定无 PDK RC 的后台仿真、PSF 解析、独立评分与归档；见 [说明](SPECTRE_RC.md) | 晶体管/PDK 设计、通用任意网表 Tool 和机器重启恢复 |
| VABench | 固定 r53/EVAS 版本、公开四工具、Pi/GLM 的一次 `v4-001` 真模型回合与原评分器终评；见 [说明](VABENCH_AGENT.md) | 这只是单题开发试点；没有形成跨任务、可重复的 Agent＋GLM 基线或原 campaign 成绩 |
| Analog Design Bench | 三题原评分器正反控；100 MHz RLC 的公开诊断、受控会话、Pi 四 Tool 桥接、后台动作恢复、冻结终评和私有 Episode 归档；另有一次真实 Pi＋GLM 自主仿真、提交、原评分器 15/15 的 development 回合；见 [说明](ANALOG_DESIGN_BENCH.md) | 单题一次通过不代表稳定表现；其它任务、Codex 条件及跨账号复现未验收 |

后续报告始终分开写明：构造夹具、本机真实进程、实验室真实仿真、真实模型回合、独立电路判定。
运行成功、结果有效和设计达标是三种不同状态。不得把正例回放、一次模型通过或环境故障归作总体成绩。
因此“VABench 单题曾跑通 Pi＋GLM”与“Chips 平台的 Agent＋GLM 闭环已验收”是不同结论；
后者仍是下述独立工作包：Analog Design Bench 已有单题单回合通过，但预先固定的重复运行和跨任务表现仍未验收。

## 工作包 1：非结构化问题接入

**目标**：让不懂代码的电路研究者从 PDF、Word、图片、表格或文字描述开始，而不必先写任务 JSON。

**当前进展（2026-09-25）**：[构造图文 D0 预试](../../examples/chips/task_authoring/README.md)
已有真实 Codex 提取、操作者确认、Spectre 构建/仿真、四实例独立检查与冻结包重放。
候选仍是固定框架下的有界 JSON；确认使用合成资料的标准答案。通用文档输入、真实专家确认、
缺失/冲突材料的真实模型澄清及 A/B/C 正式比较尚未验收，不将该工作包整体标为完成。

- 先实现可单独测试的文档提取 Tool：返回文本、表格、图片/图注及其文件哈希、页码或位置；
  OCR/视觉模型识别与原始可复制文本分开标注。保留原文件的访问边界，不把私有文档自动提交到 Git。
- 用 Agent/Skill 引导提问和任务草拟：提取电路类型、目标、固定条件、可修改项、仿真设置、输出、
  单位、约束及潜在冲突；区分复现、故障诊断、受约束设计、优化和 Tool 开发等任务类型。
  每项标为“原文明确 / 推断待确认 / 缺失”，并附来源引用。
- 把草案映射到 [任务卡模板](../../examples/chips/benchmarks/TASK_TEMPLATE.md)，由研究者确认关键物理含义、
  评价指标和允许的数据/模型访问。确认前不启动付费或商业仿真，也不把推断值悄悄写成固定阈值。
- 确认后生成带版本、来源摘要、确认记录和可见性边界的任务定义；原始资料仍在操作者私有区。
  任务可以先标记为“个人实践”，不要求虚构标准答案或 `reward`。

首版建议输出一份供人阅读的 `TASK.md`、一份待确认问题清单，以及一份机器可检查的任务契约；
来源映射至少能定位每个关键字段所依据的文件与页/区域。文件名和 JSON Schema 在试点后冻结，
不以 Skill 中自由格式的叙述代替 Tool 的稳定输入输出。

**首个验收**：使用一份含文字、参数表和电路图的代表性资料，再用一份故意缺单位或条件冲突的夹具。
前者能生成有逐项出处的任务草案，并在专家确认后形成可执行任务；后者明确列出待确认项，
阻止其晋升为正式评测。先比较人工整理结果与提取结果；不以“生成了 JSON”替代语义正确性。
没有代表性资料时，先完成接口/夹具验证，真实多模态验收记为 `not_run`。

## 工作包 2：统一任务契约与评测分级

**目标**：不同来源的任务进入相同的实验入口，但保留各自的执行器和评分器。

- 公共任务契约至少记录 task ID/版本、来源与共享权限、输入、允许修改的候选、固定环境、
  端口/单位/工艺、预算、输出指标与容差、公开反馈范围，以及提交停止条件。
- 分开记录 `draft`、`confirmed_practice`、`tool_reproduced`、`benchmark_ready` 和
  `member_reproduced` 等状态；只有证据满足对应条件才升级。不要将目录名或自称的状态当成隔离证明。
- 正式评测还须冻结开发/测试划分、独立评分器、正例、设计负例及不可评/执行故障例；
  对人工评审任务明确评审人和证据，不能和自动评分题混算成功率。
- 任务登记仍在 [benchmarks/](../../examples/chips/benchmarks/README.md)；通用 loader、
  `alphaapollo/data_preprocess/chips/` 与 `alphaapollo/common/grader/chips/` 只在首个真实通用案例
  证明需要后增加。数据准备负责 public/private 清单，纯 Grader 不暗中启动仿真。

**验收**：同一任务版本及其输入摘要能在两个新 run 中复现；非法候选/越界输入被拒绝；
公开 Agent 无法从工具或工作区读到隐藏答案；评分器对已知通过、设计失败及不可评案例给出不同状态。

## 工作包 3：执行环境、仿真 Tool 与恢复

**目标**：研究者各用自己的账号和私有配置运行相同任务；Agent 看到有用的反馈，操作者保有原始证据。

- 将预检收敛为明确结果：仿真器/版本、许可证、PDK、镜像或沙箱、路径权限、空间、依赖、
  模型 HTTPS 与任务所需端口。预检失败说明缺口，不计为电路失败。
- 活跃作业优先在服务器本地 scratch 展开；归档在私有持久区逐文件校验后再允许清理。
  保存任务/工具/后端版本、输入哈希、job ID、阶段耗时、日志和产物哈希；衡量展开、仿真、传输、
  评分及模型请求耗时，不能仅凭总墙钟归因于 NFS 或 SSH。
- `simulate` 只接受任务许可的候选与参数，给 Agent 返回公开、可操作的诊断；原始波形/日志留在归档。
  `submit` 冻结候选；隐藏终评由操作者侧启动，不能注册成 Agent 工具。详见 [Tool 规格](TOOL_TEMPLATE.md)。
- 对每个动作记录稳定 ID；SSH 掉线或重复请求先查原作业，状态未知时不重启相同仿真。
  分别测试超时、取消、许可证错误、归档失败和损坏下载。整段 Agent 进程在服务器重启后的恢复
  **尚未实现**，不能从“SSH 断开后作业完成”推断这一能力。
- 后端按任务固定：Analog Design Bench 的正式对照用经校验的 Podman 固定镜像，Bubblewrap 用于快速
  smoke/定位；VABench 当前已验证的公开 EVAS 路径是 Bubblewrap，迁移 Podman 需另做等价验收；
  Spectre/EMX 依据许可证和实验室配置使用各自后端。Docker 可作为备选，但当前不作为已验收条件。
  比较后端或服务器同机 Agent/控制机 SSH 时，应固定任务与版本，分开报告正确性、工具耗时、
  模型请求耗时和归档耗时；一次总耗时差不能证明某个执行位置更优。

**已完成的单题试点**：`rlc-rf-bandpass-100mhz` 已接公开仿真 Tool，并与操作者侧原评分器分离；
固定候选正负控、哈希关联及一次 Pi＋GLM 提交后 15/15 独立终评见[验证记录](VALIDATION.md)。
后续仍需扩展任务覆盖，并由第二位成员独立复现。

**验收**：至少一条真实工具直接回放的正负控；断线/重试不产生第二个求解进程；
终评只读取冻结候选；归档离线校验通过。另由第二位成员在自己的账号按文档部署并运行一个相同版本任务，
记录软件、工艺、镜像/沙箱、资源差异及指标容差。第二位成员验收在实际完成前保持 `not_run`。

## 工作包 4：Pi＋GLM 真实模型端到端闭环

**目标**：证明指定任务上确实由真实模型驱动 Agent 完成读取、设计、调用公开仿真、处理反馈、
提交和独立终评；把“接口接通”与“电路解题成功”分别验收。

- 先以 VABench 已有的单题试点校准 Pi、GLM、预算、公开工具与终评记录格式；
  不能把该历史回合当作新任务、不同后端或多次重复的验收。新目标是选定的一道 Analog RLC 题，
  使用工作包 3 的公开仿真 Tool 和既有操作者侧原评分器。
- 固定任务提交、上游源码/镜像、Pi 与 GLM 版本、提示和工具集合、公开仿真次数、模型请求次数、
  单次/总时间及预算。模型不读取参考解、隐藏测试或最终评分器。先用无模型正负控确认环境，
  再开始真模型回合；脚本模型响应只检验协议，不计入 GLM 成绩。
- 优先在 lab-server 同机运行；记录模型 HTTPS 可达性、Pi/MCP/仿真器资源及分阶段耗时。
  若该环境的模型请求不可达，可在已验证的控制机 Pi＋SSH 路径运行同一任务，并把执行位置记为条件。
- Agent 每次可读取本回合的公开历史和 Tool 反馈。保存模型请求事件、工具输入输出、候选版本、
  仿真 job、冻结提交及终评收据；若它依据失败反馈修复候选，单独标记为“反馈驱动修复”证据，
  不把一次调用公开仿真就描述成已证明多轮诊断能力。

**验收分层**：① **协议闭环**：至少一次真实 GLM 请求和公开仿真，由 Pi 自主调用工具并完成或明确停止；
无人工代替提交/修改，日志能对齐候选与终评输入。模型设计失败也可以通过这一层。
② **单题解题**：在同一冻结任务、预算和真实模型条件下，Agent 的提交由独立评分器判为达标，
公开记录可复核且未借用参考答案。③ **稳定表现**：按预先固定的任务集和重复次数运行全部计划样本，
报告成功率、失败与环境阻塞；一次单题通过不能达到这一层。
上述三层分别记录 `passed`、`failed`、`blocked` 或 `not_run`，不能合并写“Agent＋GLM 已跑通”。

## 工作包 5：完整 Episode 与可分析轨迹

2026-09-24 已增加[离线 Episode 报告](EPISODE_REPORT.md)，并对真实历史归档验证成功、修复后成功、预算耗尽未提交三类记录。它覆盖已保存证据的关联、查看与校验；完整请求捕获、跨账号复现、更多任务适配及 Memory 隔离验收仍未完成。

**目标**：既让 Agent 在当前任务内利用先前公开反馈，也让研究者看清长任务如何拆解、试错和停止。

- 用 episode/run ID 关联模型请求、Agent 消息、工具调用、远端 job、候选快照、仿真产物和终评分数。
  记录实际可见工具集合、模型与版本、预算、时间戳、错误/恢复、停止原因；原始事件与便于分析的摘要
  并存。对缺失的 provider 用量或内部推理标注 `not_available`，不推测。
- 当前 episode 内，Agent 接收自己的对话和公开工具结果；长上下文可提供从公开事实生成的状态摘要，
  但必须标记摘要来源。完成后封存的整个 episode 不自动在每轮重发给模型。
- 下一次任务使用新会话，默认不注入上一次的原始轨迹；跨任务 Memory 是另一个显式实验条件。
  已有 VABench r53 正式条件禁止跨任务 Memory，不能通过改 task ID 绕过。
- 区分研究者可审计的完整私有包、Agent 可见的当前任务材料，以及可分享的脱敏摘要；
  API Key、工艺资料、隐藏评分与其他人的私有轨迹不进入模型可读目录。

**验收**：给定 run ID，可按顺序还原每次修改、仿真反馈与后续决策，定位错误归属和最终候选；
从归档核对最终评分对应的候选哈希；检查一次新会话不能读取旧 episode 或隐藏评分。
模型实际未输出的内部思考不列为“完整可观测”。

## 工作包 6：任务扩展与可迁移 Tools

**目标**：先获得少量有区分力的任务，再根据真实失败模式改进工具，而非靠增加工具数量。

- VABench：保持原 r53/EVAS 评分器和已验收路径，逐步扩大公开任务与模型样本；不将单题结果写成全套成绩。
- Analog：先完成一题公开 Tool/Agent 闭环，再扩展另一个 RLC 和 OTA；各题沿用各自固定上游版本。
- Spectre：在专家提供晶体管/PDK 案例、模型与指标后，设计受限候选输入和公开诊断；固定 RC 仅为后端基线。
- EMX：需要真实布局生成规则、工艺、端口、频率与专家认可的指标；厂商样例不能替代设计任务。
- 每个新 Tool 先有直接调用入口、固定输入输出、失败语义和成功/失败/不可评夹具；
  再暴露给 Pi。是否拆成更细粒度工具，通过消融比较决定。

**验收**：至少一个新增真实电路任务通过专家检查、正负控、独立评分与成员复现；
相应 Tool 脱离 Agent 可直接回放，在相同任务版本下至少由一个 Agent 入口正确调用。
尚无专家给定的工艺/阈值时，只交付带待确认项的任务草案，不编造可执行参数。

## 工作包 7：对照实验、经验库与持续改进

**目标**：回答“任务、Tool、Agent、模型及 Memory 各自带来什么”，避免从一条好轨迹归因。

| 对照 | 固定项 | 唯一改变项 | 主要指标 |
| --- | --- | --- | --- |
| Tool 直接回放 | 输入、软件/工艺、评分 | Tool 实现或反馈版本 | 正确性、故障率、耗时、资源 |
| Tool 接口/集合 | 任务、Pi、模型、预算、Memory 关闭 | 名称、粒度、说明或可见集合中的一项 | 有效调用率、冗余调用、成功率、成本 |
| 模型 | 任务、工具、Agent、预算与环境 | 模型/采样配置 | 独立达标率、请求量、错误类型 |
| Agent | 尽量相同的模型、任务和工具 | Pi/Codex 或调度策略 | 轨迹结构、耗时、停止与修复行为 |
| Memory | 任务、模型、Agent、工具、预算 | 冻结经验快照 off/on | 独立任务收益、检索成本和误用率 |

- 先固定任务集、版本、预算、指标、停止规则、计划运行数和划分，再做小样本试验与正式重复运行。
  逐次记录所有成功、失败和环境阻塞；报告样本数、波动和适用条件。不能把一次通过当作成功率。
- Markdown、JSON、XML 等提示呈现方式可作为后续小规模对照因素；机器任务契约与评分规则保持一致，
  一次只改变 Agent 看到的呈现方式，不预设任何格式对所有任务最好。
- 经验从专家材料与开发任务轨迹提出，记录来源、适用工艺/软件、可复现步骤、正反例及审核状态。
  只有复测或专家确认后才进入冻结、只读的跨任务快照；允许撤销。个人实践轨迹可提出候选经验，
  不自动改写生产 Tool、Skill、评分器或模型权重。
- 测试任务的隐藏答案、终评反馈和同源变体不进入其评测前的 Memory；在线学习需另设顺序与反馈协议。
  研究者可以复盘轨迹提出改进，再以新版本和对照实验验证。

**验收**：每个结论能追溯到固定的任务/工具/模型/后端/预算版本与完整运行列表；
memory-off/on 使用同一冻结快照边界和独立任务，报告成功率、无效提交、仿真次数、
模型用量（可获得时）、各阶段墙钟和失败类型。证据不足时结论为“尚不能判断”。

## 建议实施顺序与近期停止线

任务接入试点与 Analog 公开 Tool 可以并行；任何一条缺材料时，不应阻塞另一条。

| 次序 | 最小交付 | 完成条件 |
| --- | --- | --- |
| 1A | 一份真实多模态材料的任务接入试点；材料暂缺时先做可审查草案/来源协议 | 关键约束经用户确认，未确认项不会流入执行或正式评分 |
| 1B | 一题 Analog RLC 的公开仿真 Tool 与冻结提交 | 无模型正负控、公开反馈及原评分器输入可关联，重复调用不重复求解 |
| 2 | 该题的真实 Pi＋GLM 回合 | 分别报告协议闭环、独立解题和重复运行结果；失败回合仍保留完整轨迹 |
| 3 | 跨后端 Episode/环境报告与第二位成员复现 | 可定位所有模型/工具/job/产物，真实断线及归档验收，不混淆各执行条件 |
| 4 | 扩充任务/工具、做受控对照、引入冻结经验快照 | 每项能力有独立正确性证据与独立任务上的比较结果 |

上述顺序允许专家并行整理 Spectre/EMX 任务材料，但这些材料不应阻塞已经具备公开仿真条件的
VABench/Analog 工作。每个工作包按 [SOP](DEVELOPMENT_SOP.md) 留下可复用测试、私有原始证据与
准确状态；Bio、Robotics、Math 仅作源码/设计参考，不属于 Chips 运行验收。

## 第一条可重复输入

从实验室已有的 EMX 厂商 exind.gds 提取顶层 ind 的多边形和标签，形成现有
[JSON 转换器](../../examples/chips/emx/json_to_gds.py) 支持的输入。厂商示例及其派生输入不随本仓库分发。

验证内容：

1. 输入含 395 个多边形、2 个端口标签；单位为微米，GDS 精度为 1 nm。
2. 重建后逐层做几何 XOR，三个层的差异面积均为 0，标签位置和名称一致。
3. 厂商原始 GDS 直接运行作为同环境对照；原任务恢复后及修复后的两个新任务，Y/S 数值均与该对照一致。
4. 检查频率、矩阵维度、有限数值、互易性及所有下载产物的哈希。
5. 修复后的完成任务 resume 保持同一 job ID；远端事件记录只有一次 EMX 进程启动。

配置限制：一次一个任务，EMX 单线程、1 GiB 内存目标、Harness 整体 60 秒 deadline，
最多两次传输尝试。上述设置是本次小样例的配置，不是所有电路的默认资源承诺。

修复后两次新任务的 CLI 耗时为 16.33 / 16.86 秒，EMX 进程耗时为 0.81 / 0.87 秒；
完成任务 resume 耗时 3.03 秒。这些是功能预试记录，没有足够样本估算 p95 或比较部署方案。
同求解器对照支持转换和执行一致性；不能替代独立电磁参考或专家定义的电感/Q 值验收。

## 真实执行发现的缺陷

首次提交后 EMX 已成功，控制端却收到 state=unknown。
该运行的 NFS 文件修改时间比 worker 写入的事件时间落后约 108 秒。
原状态检测拿执行节点时钟减去文件系统 mtime，错误地认为心跳已过期。

修复位于 [ssh_worker.py](../../circuit_harness/execution/ssh_worker.py)：
由提交端先写入 job_submitted 事件，随后用执行节点写入的应用事件时间判断新鲜度。
没有可信事件、事件过期或来自未来时仍返回 unknown；不会通过延长阈值或重新提交掩盖问题。
最终 result 继续优先于心跳。已有任务的恢复保留原版本/内容身份检查。

[回归测试](../../tests/chips/test_simulator.py) 通过实际 worker CLI 注入文件时间偏差，
覆盖新鲜心跳、过期心跳、未来时间和缺失心跳。复现经历了 Red → Green；
受影响的 Harness/Workflow 测试共 29 项通过。真实服务器复测也通过。

## 如何选择后续可复现的组件

| 候选 | 适合承担的部分 | 接入前还需验证 |
| --- | --- | --- |
| 当前 Apollo Chips + EMX 厂商例子 | 现成作业、日志、传输、恢复与 GDS 链路；已有上述实测证据 | 运行中断线、取消/超时、真实电路指标及更大样例 |
| [virtuoso-bridge-lite](https://github.com/Arcadia-1/virtuoso-bridge-lite) | Spectre 本地/SSH 执行及 PSF 读取；本机源码具有 SpectreSimulator.local | 当前节点的许可证；固定 Bridge 提交与配置，完成 RC 解析公式验收 |
| [ngspice 官方批处理/控制语言示例](https://ngspice.sourceforge.io/ngspice-control-language-tutorial.html) | 无商业许可证的电路回归基础；先用无 PDK RC，之后再选开放模型 | 选定安装版本、输出解析器和跨环境容差；此节点尚未实跑 |
| [IIC-OSIC-TOOLS](https://github.com/iic-jku/IIC-OSIC-TOOLS) | 提供 ngspice、Xyce、openEMS 及开放 PDK 的容器环境 | 容器运行权限、存储与下载；固定镜像 digest 和 PDK 版本，不能只使用 latest |

容器负责环境复现，仿真器负责求解，Harness 负责执行与证据，任务集负责输入与判定。
这些层各自固定版本和验收，避免把装好一个大镜像当成整个平台已经稳定。
本次只核查候选资料，没有安装或拉取这些开源环境。

## 下一步验收顺序

1. **固化 EMX 基线**：保留小样例和原始失败；再验证运行中断开控制端、超时与取消。
2. **完善服务器执行**：接入同机执行后端、转换与解析环境，比较相同任务下的端到端耗时；
   优先减少不必要的 SSH 往返及全量结果下载。
3. **解锁 Spectre 和开源对照**：确认许可证失败原因；以同一 RC 的解析解分别验收后端。
4. **再接真实 Agent**：明确模型入口、认证与可发送的数据，以固定 Tool 和任务验证一次真实工具调用。
5. **扩展到专家任务**：指定工艺/端口/频段、可修改参数、参考结果及容差，再加入电感或模拟电路任务。

## E4：真实工具回放与断线恢复

**先决条件：E1–E3 通过。** 所有仿真都在 lab-server；不开模型请求，不修改共享主机／网络配置。

| 编号 | 操作／对照 | 数量 | 验收 |
| --- | --- | --- | --- |
| R1 | 两任务各用固定正确候选、错误候选，经旧／新工具路径执行公开仿真后冻结、独立终评 | 2 任务 × 2 候选 × 2 路径 = 8 个新会话 | 新旧公开结果、冻结输入和原评分器结果等价；错误候选选择可提交但电路不达标的已知负例 |
| R2 | 同一 vaBench 正例脚本，经服务器 local 与本机 SSH 调用新环境 | 2 个新会话，每会话一次仿真 | 相同候选和后端产生相同语义结果；local 不引入第二份服务器状态 |
| R3 | 新环境经 SSH 启动已确认接收的 vaBench 仿真，在 job 未结束时终止本次客户端，再重建／查询原 ID | 1 个隔离会话 | job 在重连前完成或持续独立推进；同 ID 一次执行，恢复收取后哈希一致 |

R3 若实际仿真太快，先用隔离 worker 延迟固定输入的执行，明确延迟是测试注入；
未观察到断开时作业仍在运行，该次不能计为断线中运行的证据。不得重启服务器或切断他人网络。
退出 Runtime 后如何调用恢复入口也必须留证；不只用已有独立 CLI 探针代替新适配器的生命周期验收。

公开反馈比较剔除限定的 ID／路径／时间字段。确定性字符串／候选字节要求一致；浮点指标使用
任务原有容差。若现有任务没有可用于新旧数值等价的容差，先用旧路径重复测量并记录选择依据，
在新路径结果揭示前冻结该容差；不因新结果失败而放宽阈值。
R1 共 8 次公开仿真与 8 次终评，R2／R3 共 3 次公开仿真；不额外触发终评来重复计数。
上述基本计划为 11 次公开调用；若需容差预试，先单列追加数量与目的。
scorer 内部可能运行多次仿真，需单独计数，不能称为只有 19 次求解。

## E5：固定条件下的真实模型回合

**先决条件：E4 完整性验收通过。** 首轮全部 Agent 在 lab-server；隔离部署位置差异，先验证 Runtime 迁移。

| 条件 | Agent 路径 | 任务 | 回合数 | 用途 |
| --- | --- | --- | --- | --- |
| M1 | 旧 Chips 直接 PiSession＋GLM | vaBench `v4-001` | 3 | 同期旧路径基线；历史成功记录不能替代 |
| M2 | 共享 ExternalAgentRuntime＋Pi＋GLM＋新 Environment | 同上 | 3 | 检查迁移后真实 MCP 与轨迹闭环 |
| M3 | 共享 AlphaApolloAgentRuntime＋同一 GLM 服务＋同一任务环境 | 同上 | 3 | 检查原生 Agent 替换；不是与 Pi 完全相同的模型上下文 |
| M4 | 共享 ExternalAgentRuntime＋Pi＋GLM＋Analog 环境 | Analog 100 MHz RLC | 3 | 检查第二任务接入无需另一套 Agent 循环 |

总计 **12 个真实模型 Episode**。3 次仅用于发现偶发集成问题、观察解题波动，不能支撑统计优劣。
先按 M1→M2→M3→M4 各跑一个；若工具／证据完整性存在故障，先停止后续回合。
集成门槛通过后，第 2 轮按 M2→M1→M4→M3，第 3 轮按 M3→M4→M1→M2 执行；全部尝试保留，不挑选成功结果。
电路未达标属于结果，可按原计划继续；修代码、换预算或换 prompt 后必须使用新的条件版本，不能补到旧组。

### 预算与模型设置（建议值，实施时须冻结为实际配置）

| 项目 | M1–M4 建议条件 | 必须验证的执行语义 |
| --- | --- | --- |
| model | `glm-5.3-flash`，同一服务与账号类型 | 记录请求值和服务可返回的实际模型标识；不能保证服务端权重永不变 |
| thinking | 显式 `low` | 按现有 Pi 映射核对原生 backend 的 provider 参数；设置名相同不等于已生效 |
| 模型请求 | 每回合最多 12 个逻辑请求 | 同时记录 HTTP attempts／重试；两 Runtime 的计数单位先对齐 |
| 单请求输出 | 8192 tokens | 属于请求给 provider 的上限，记录响应 usage；解释是否含 reasoning，不伪装为精确总费用上限 |
| 请求大小 | 64000 bytes | 比较时约定在各自实际发往 provider 的完整请求体计量；不能混用 prompt 字符数 |
| 公开动作／仿真 | 每回合 24 个动作／4 次公开仿真 | 由任务 session 强制；沿用原有错误调用、重复 ID 的计费规则 |
| 时间 | Agent 1200 s；单次公开仿真 120 s | 与 MCP 等待、SSH 查询、后台 job 的期限分别配置；模型结束不取消已收任务 |
| 终评 | 独立时间／资源期限，沿用任务已验证配置 | 在操作者运行记录里填写具体值；不记入模型预算；仅确认冻结后执行 |

这些值形成新实验条件，不是复述现有历史默认。两 Runtime 的 request-size／请求数守卫若尚不支持，
应在 E1 补最小能力并验收；做不到时将该条件记为 blocked 或明示降为非等预算兼容性试验，不能悄悄略过。
原生 backend 的 GLM thinking／tool-call 格式先用构造请求检查，再由首个真实回合核对。
超出当前可确认能力时不发起完整 12 回合；不通过自动改成另一模型让表面验收通过。

最多 144 个逻辑模型请求、48 次公开仿真、12 次终评；输出预算算术上限为 1,179,648 tokens，
不是服务商计费或全部 token 上限（输入重传、重试和 reasoning 计量需另记）。单独限制 HTTP 重试，
默认建议关闭自动重试以便归因；若不能控制，记录能力缺口。无需本地 GPU；CPU／内存峰值实测，
先串行并发度 1。Agent 预算总和最多 4 小时，另加预检、终评、收取；不是承诺总周转时间。

### 如何判断成功与失败

- **接入通过**：真实请求和工具发生、错误／停止可解释、终态可信、记录可关联、公开边界未破坏。
- **提交闭环通过**：每个新条件 M2–M4 至少一次由真实模型发起仿真并确认提交，随后独立终评且归档完整。
  若 3 次均未提交，记为尚未取得完整闭环证据；不再自动加跑或提高预算来凑成功。
- **设计表现**：逐次报告原始分数／单位／阈值与预算消耗。可评分的失败也是有效数据；无效执行不能写零分。
  Analog 原始连续 reward 与逐测试结果分别保留，没有原任务定义的二元 success 时不造通过率。
- **迁移结论**：E1–E4 通过而 E5 设计分数下降时，先比较提示、schema、错误反馈、预算和实际模型参数；
  12 次探索不能排除模型随机性，也不支持“新 Runtime 更强／更差”的定量结论。

## 轨迹与耗时：每个 Episode 要能回答什么

保存既有原始日志，加上 Runtime／Environment 的标准记录和 ID 映射；不以合并 JSON 替代原件。

| 证据 | 最小内容 | 可见性／限度 |
| --- | --- | --- |
| 输入 | system、用户任务、工具 schema、公开文件／候选摘要、预算、Agent 固有指令来源 | 本机可控部分完整保存；外部 CLI 未公开的内部指令标 unknown |
| 模型 | 每次可观察请求／返回、消息／tool call、usage、错误与停止原因 | 原生 backend 记录实际边界；Pi raw events 与预算记录保留；隐藏思维不保证可见 |
| 动作 | episode→call→action→job 的映射、参数、公开返回、候选前后摘要 | 重试共享逻辑 action ID，独立记录 attempt；不凭文本猜关联 |
| 仿真／终评 | worker／软件版本、起止时间、日志、产物哈希、冻结输入和 scorer 结果 | 模型只看到公开反馈；原始完整归档供操作者复核 |
| 完整性 | 文件清单、摘要、缺失／截断／未知字段、模型／动作观测覆盖 | 密钥和 bridge token 不保存；缺失不补造，不能把未测量写成 0 |

耗时至少分模型等待、工具客户端往返、服务器排队／展开／仿真、终评、归档／传输。
单机持续时间用单调时钟；跨机使用 ID 关联和各自时长，不直接相减未校准时钟。
父子区间重叠不能简单相加；MCP 往返减去服务器阶段也不能直接宣称是纯网络延迟。
E4 的 local／SSH 只验语义，不凭各一次运行宣称哪条更快。

用现有离线报告入口验收：断网后仍能沿时间线回答“每一步输入、调用工具、结果、候选变化和花费多久”。
任务拆解只从实际消息和动作报告；未输出的计划不能推断成 Agent 的内部思考。
敏感原始证据留私有 run 存储；Git 保存脚本、脱敏 fixture、条件摘要和结论。
